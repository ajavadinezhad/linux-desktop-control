A post-ARM stream drop remains terminal. Retained challenge mode also requires its separate mouse/touchpad-only post-ARM challenge: issue the move-then-still, no-key/no-click cue only with `readiness_stage:"post-arm-pointer"`, `post_arm_state:"waiting-motion"`, acknowledged notice phase `post-arm-pointer`, known delivery and positive remaining time. Waiting-quiet requires stillness; expired/resuming/verified/failed states do not justify another cue. Require `post_arm_verified:true`, current readiness and a fresh inspected startup image before task input. Never reuse the initial cue; close the second notice before final readiness.

Select the actual source: mouse requires exact `MODEYIELD2/MODEYIELD2_OK`; touchpad requires `MODEYIELD3` admission. ## Retained sharing and automatic return

Only when authorized, select `interruption_policy:"retain-sharing"` with native monitoring. Physical motion cancels pending work and queued requests, releases virtual input, invalidates observations and suspends capture/input while retaining the original portal and private observation. Manual pause/resume also require retained sharing; default policy closes instead.

`pointer_motion_return:true` separately permits one relative cursor return after 1.5 seconds of observed quiet, released input, clean queues and a current-epoch resume handshake. In passive mode actual selected-source movement must belong to the current yield epoch; contact, metadata, an earlier calibration or an old pause cannot substitute. Only the same consent, foreground, monitor mapping and valid in-monitor last confirmed destination permit return. No saved destination, changed foreground or off-monitor pointer leaves motion return paused. No click, text, scroll, interrupted step, old request or focus activation follows automatically. New movement yields again without correction. Inspect a fresh observation after return before selecting task input. Ordinary mouse motion without this explicit return option does not imply automatic continuation.

Manual Pause stays sticky even after motion/quiet; only explicit `desktop_resume` with current `pause.pause_id` leaves it. Wrong/stale pause tokens leave it paused. `sharing_active:true` while paused does not mean capture/input are allowed. All original leases and cancellation remain active; privacy Stop is distinct from a retained pause.

- `keyboard_policy:"pause-recover"` additionally requires click pause, retained native monitoring and `context_change_policy:"pause-recover"`, with exact `KEYPAUSE1`. Brief inconsistent touch/tool snapshots get only the existing fixed bounded recheck; persistent inconsistency terminates.

Diagnostics may retain fixed coarse idle/rejection categories only after raw/lifecycle descriptors close. They contain no device identities, raw values, coordinates, key contents or exact timestamps. Continuous armed health is not complete device coverage.

## Explicit two-monitor window setup

Only exactly two verified unrotated, unmirrored, unambiguous logical monitors are admitted. Each operation needs fresh current-window observation, explicit task authorization and a separate `focus_transition:true` call. Read-only settings must show the exact default configured shortcut; never alter settings to make it work. Keep the same foreground identity and mapping through modifiers and final activation, then require the same window wholly inside the destination before publishing. Wrong/no arrival, owner/layout/binding/authority loss or protected UI refuses without retry, fallback, focus reclaim or direct window-management calls. When the focused window is off the shared monitor, observer identity/frame are not proof its contents were seen.

- `window_move_to_shared:true`, exact `action:{type:"keys",keys:["Super","Shift","Left"]}` (or Right/Up/Down): source window must already be wholly on the other monitor, with a direction unambiguously toward the shared one. The destination is the shared monitor.
- `window_normalize_for_move:true`, exact `action:{type:"keys",keys:["Alt","F10"]}`: a partly off-screen source frame's origin/titlebar and center must unambiguously belong to the other monitor, without intersection of the shared one. It must become wholly source-contained; a later move is separate.
- `window_fit_shared:true`, same exact Alt+F10 action: the oversized frame's center and titlebar midpoint must be on the shared monitor, whose intersection is strictly largest. Its origin may lie outside. Require full shared containment after.

These are resize toggles, not claims of maximize state. Never combine flags, batch with more actions or automatically repeat a toggle. Inspect each returned image before choosing the next operation.

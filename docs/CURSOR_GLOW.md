# Optional actual cursor glow

The candidate changes the actual Xcursor theme pixels, not an overlay, ring, duplicate pointer, pointer hiding, or input grab. Source: installed `/usr/share/icons/Yaru`, Ubuntu Yaru, https://github.com/ubuntu/yaru. Cursor assets are attributed to Sam Hewitt and Yaru contributors under CC BY-SA 4.0 (see the included distribution copyright). Modified assets add cyan glow behind the original pixels. They retain original image dimensions, hotspot, nominal size, delay, frame order and aliases. Glow can be clipped by an original canvas edge. Windows `.cur`/`.ani` auxiliary assets are preserved unchanged and are not claimed to glow. Client-provided custom cursors may ignore this theme.

`cursor-theme/build.py` uses Pillow and bounded Xcursor parsing. It builds into a new directory only and never touches desktop settings. The generated candidate is reviewable before installation. Use a unique `CodexGlow-…` theme name for each installed candidate. The project code and these third-party derivative assets have distinct licensing; deferring a project reuse license does not remove the theme attribution/share-alike conditions.

Activation must be explicitly disclosed: this temporarily changes the desktop-wide GNOME cursor-theme preference, so it affects other applications too. The injected `CursorThemeLease` adapter must read the user override separately from the effective default, implement set/reset, and install only validated generated assets into an owned private theme directory. The lease journals the original override (including unset) before setting, keeps a kernel exclusive lock, and restores only while the preference still equals its unique theme. A user theme change is preserved.

The integrated CursorGlow Controller runs an independent worker process and must call `poll(owner_alive=False)` on owner death and `poll()` for the three-second heartbeat deadline, call `close()` for normal/error/session closure, and call `recover()` on startup (the backend does this for its own journal). Importing the module does nothing. The low-level lease module does not launch a watchdog; cursor_glow_service.py provides the worker, and desktop_start(cursor_glow=true) is the explicit opt-in. If both owner and watchdog are killed or the machine loses power, restoration waits for startup recovery; immediate crash restoration cannot be guaranteed. Do not enable without this lifecycle integration. Keep the existing passive label and focus protections independent of theme state.

Isolated lease and real-subprocess fake-settings tests cover explicit opt-in, unset restoration, exclusive ownership, preservation of user changes, expiry, owner loss/startup recovery, and nonblank/pixel-header/hotspot/frame preservation. The 0.7.4 live check enabled the theme, showed cyan glow on the actual pointer, and restored the original Yaru theme after cleanup. Client-specific coverage and hard-crash restoration remain limited as described above.
